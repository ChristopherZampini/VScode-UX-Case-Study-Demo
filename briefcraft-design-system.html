Reusable HTML document system · Extracted from the Briefcraft CMMC brief

Build compact, executive-ready briefs with consistent structure.

This reference captures the visual rules, CSS tokens, page geometry, component patterns, audience indicators, print behavior, and writing conventions used in the source document.

Best for Decision briefs, implementation plans, executive readouts, research summaries, compliance documents, and multi-page printable HTML.
Visual DNA

Core design principles

Print-first structure

Every document is composed as a sequence of US Letter pages with predictable internal padding and page breaks.

Editorial hierarchy

A small eyebrow sets context. A large headline states the decision. A muted subtitle explains the use case.

Modular information

Content is divided into reusable cards, option grids, flows, callouts, tables, and ownership-labeled sections.

Restrained palette

Neutral paper, white cards, near-black ink, one orange accent, and semantic audience colors.

Dense but controlled

Small type and tight spacing are balanced by short paragraphs, borders, clear grouping, and strong headings.

Audience clarity

Every section can identify who acts, who supplies input, who owns work, or who shares a decision.

  • Use one dominant message per page. Secondary sections should support the page headline.
  • Use full-width components for conclusions, critical context, and complex tables.
  • Use two-column cards for supporting content. Do not fill every space simply because it exists.
  • Keep ornament minimal. The visual identity comes from proportion, contrast, borders, and semantic labels.

Page system

Page anatomy

Canvas

8.5in × 11in. Paper background. 0.39in internal padding.

Header ratio

1.38fr content column and 0.62fr metadata column. 18px gap.

Main grid

Two equal columns with 11px gap. Use .full for spanning sections.

Screen treatment

24px page margin, subtle border, and restrained shadow.

Print treatment

No outer margin, border, or shadow. Fixed Letter dimensions.

Responsive treatment

Below 700px, collapse headers, content grids, and multi-card rows to one column.

Web-informed safeguards

Accessibility and readability rules

Do
  • Use visible text with every audience color.
  • Use the darker --accent-text for small orange text.
  • Keep body copy black or muted gray on light surfaces.
  • Use .accessible when the audience benefits from larger type.
  • Keep headings, lists, and tables semantically structured.
  • Test browser zoom at 200 percent and confirm no horizontal clipping.
Do not
  • Use orange body text at the source accent value.
  • Communicate ownership with a border color alone.
  • Shrink body text further to force content onto a page.
  • Use long all-caps sentences.
  • Put essential details only in footnotes or tiny source text.
  • Lock screen layouts to Letter width on mobile.
Contrast note: The original orange accent is appropriate for bars, borders, filled tags with white text, and large emphasis. Its contrast against white is not sufficient for small normal text, so this kit adds a darker orange text token while preserving the original visual accent.

The responsive and print rules in this kit follow standard CSS media-query and paged-media patterns. Sections use break-inside: avoid to reduce awkward splits. WCAG 2.2 calls for at least 4.5:1 contrast for normal text and 3:1 for large text.

Content behavior

Writing and composition rules

  • Write the page H1 as a conclusion, directive, or decision.
  • Use the eyebrow for organization, topic, and document type.
  • Limit the subtitle to the minimum context needed to interpret the page.
  • Use one or two short paragraphs per section.
  • Use lists only when the items are genuinely parallel.
  • Use strong labels before explanatory text in warning and confirmation boxes.
  • Use a three-option pattern when leadership must compare paths.
  • Mark one option as recommended. Explain why in plain language.
  • Use a five-step flow for sequences. Use a table for comparisons.
  • Place detailed sources on the last page or in a dedicated full-width section.
  • Expand acronyms on first use when the audience may not know them.
  • Remove drafting notes, presentation advice, and other meta commentary.

Final check

Pre-delivery checklist

  • All pages print at Letter size.
  • No section is unintentionally split.
  • No text is clipped by the footer.
  • Page numbers and footer labels are correct.
  • Every semantic section has a visible text label.
  • Small accent text uses the darker token.
  • Body text remains readable at browser zoom.
  • Mobile layout collapses to one column.
  • Only one primary recommendation dominates each page.
  • Sources and disclaimers are clearly separated from main content.
  • No external fonts, scripts, or CSS dependencies are required.
  • No meta-writing language appears in the final audience document.
